# Instruction Files

GitHub Copilot CLI loads custom instructions from a hierarchy of files. The `--no-custom-instructions` flag (verified in `copilot --help`) confirms loading from "AGENTS.md and related files".

## `copilot init` (verified)

```bash
cd /path/to/repo
copilot init
```

From `copilot init --help`:

> Initialize Copilot instructions for this repository. Analyzes your codebase using a restricted set of read-only tools and generates a `.github/copilot-instructions.md` file with contextual guidance for Copilot, including build and test commands, coding conventions, project structure, and technology stack.

This is the canonical bootstrap. Run it once per repo.

## AGENTS.md format

`AGENTS.md` is a plain markdown file at the repo root (or git root). No frontmatter required. Copilot reads it as-is and prepends it to the system prompt for the session.

Example:

```markdown
# Project conventions

This is a Python Flask + React monorepo. Backend in `backend/`, frontend in `frontend/`.

## Build and test
- Backend: `cd backend && pytest`
- Frontend: `cd frontend && npm test`

## Coding conventions
- Python: black formatter, mypy strict, 4-space indent
- TypeScript: prettier, eslint, no `any`
- Commit messages: conventional commits

## DO NOT
- Touch `database/migrations/` without asking
- Run `git push` automatically — always confirm
```

## Path-scoped instructions `[UNVERIFIED]`

GitHub's docs claim path-scoped instruction files with `applyTo:` frontmatter:

```markdown
---
applyTo: "src/api/**/*.py"
---

# API conventions
- All endpoints return JSON, never plain text
- Authentication via JWT only
- Rate limit: 100 req/min per IP
```

These files live in `.github/instructions/<name>.instructions.md`. Copilot picks the matching one for files you're editing. Confirm on first deploy — the local 1.0.21 install can be tested by creating one and editing a file in the matching path.

## User global `[UNVERIFIED]`

Plausible location: `~/.copilot/copilot-instructions.md`. Loaded for all sessions on this machine. Verify with:

```bash
mkdir -p ~/.copilot

# Global instructions test

```

## Cross-tool canonical pattern

The cross-tool portability rules (see `research-for-skills/cross-tool-portability/agents-md-canonical.md`) recommend:

- **Canonical content in `AGENTS.md`** (repo root)
- Thin pointer files for Claude (`CLAUDE.md`) and Gemini (`GEMINI.md`) — either `@AGENTS.md` imports or symlinks

`AGENTS.md` is the natural choice because:
- Copilot reads it natively (verified)
- Gemini supports `@file.md` imports
- Claude `[UNVERIFIED]` reads it natively (G2 first-boot test)

## Disabling custom instructions

```bash
copilot --no-custom-instructions -p "..." --allow-all-tools
```

Useful for:
- Reproducible CI runs
- Debugging: is the instruction file affecting behaviour?
- Sandbox testing
- One-off tasks that should not pick up project conventions

## Anti-patterns

| Don't | Why |
|---|---|
| Put secrets in AGENTS.md | Plaintext, committed. Use env vars + `--secret-env-vars` to redact. |
| Make AGENTS.md > 5 KB | Context budget. Use multiple smaller files (`docs/<topic>.md`) referenced from AGENTS.md. |
| Skip `copilot init` | The bootstrap is much better than nothing — it analyses the actual repo. |
| Diverge AGENTS.md from CLAUDE.md / GEMINI.md silently | Use the canonical pattern: AGENTS.md is the source, CLAUDE/GEMINI are pointers. |
| Assume `.github/instructions/**/*.instructions.md` works without testing | Path-scoped is research-grade. Verify on first deploy. |
| Edit `.github/copilot-instructions.md` and forget about AGENTS.md | Both load. They can conflict. Pick one as canonical. |
