## Image sitemaps

Source: https://developers.google.com/search/docs/crawling-indexing/sitemaps/image-sitemaps (page
updated 2025-12-10).

| Rule | Detail |
|---|---|
| Namespace | `xmlns:image="http://www.google.com/schemas/sitemap-image/1.1"` |
| Tags | `<image:image>` containing `<image:loc>`. Nothing else is read |
| Limit | Up to 1,000 `<image:image>` per `<url>` |
| Deprecated | `image:caption`, `image:title`, `image:geo_location`, `image:license` (removed in 2022; the announcement dates from May 2022). Leave them out |
| Placement | Inside the normal page sitemap entries, or in a separate sitemap listed in the index |
| What it does | Helps Google discover images, for example ones loaded by script. It does not make an image rank |

Sitemaps are usually generated by the platform or an SEO extension: check the output rather than
assume, including that gallery images (not only the main image) are listed where they matter.

## Images on a CDN or another host

`<image:loc>` may point to another domain, so CDN-hosted images can be listed, **as long as both domains
are verified in Search Console** (Google's condition). A third-party host whose domain you cannot verify
does not meet it; serve images from a host name you control (a CNAME on your own domain). The image host
must also allow Googlebot and Googlebot-Image to crawl the files (its robots.txt), and the URL should stay
the same for the same image.

## Merchant Center image_link

Source: https://support.google.com/merchants/answer/6324350; size change:
https://support.google.com/merchants/answer/16989427.

| Rule | Detail |
|---|---|
| Minimum size | **500 x 500 pixels for all product categories**: warnings from 2026-04-14, enforcement from 2027-01-31. Until then the older minimums (100 x 100, 250 x 250 for apparel) apply (that the older figures still apply is from third-party sources: LIKELY). Some small images are auto-optimised and flagged "Image too small for upcoming enforcement" |
| Recommended | About 1,500 x 1,500 |
| Maximum | 64 megapixels, 16 MB |
| Formats | JPEG, WebP, PNG, GIF, BMP, TIFF; the extension must match the format. Animated GIF: not addressed (UNCERTAIN) |
| Content | The product itself, accurately; a placeholder, a generic graphic, a single-colour image or a border is not allowed |
| Prohibited overlays | Superimposed promotional text, calls to action, prices, shipping information, watermarks, copyright symbols, added logos, store names, barcodes, QR codes, condition labels (some category exceptions). Branding that is physically part of the product or its packaging is allowed |
| URL | ASCII, RFC 3986, 1 to 2,000 characters, stable, crawlable by Googlebot and Googlebot-Image |
| AI-made or AI-edited images | Keep the IPTC `DigitalSourceType` metadata, including Product Studio output |
| Consequence | Promotional elements "will cause an image disapproval"; other failures stop the item appearing on Google surfaces, with a Diagnostics notice. Automatic image improvements fix some minor issues |

The feed reads the image file; alt text is not a feed field. Alt still matters on the landing page, which
Google also crawls.

## Merchant Center additional_image_link

Source: https://support.google.com/merchants/answer/6324370.

- Up to 10 additional images, each meeting the `image_link` rules.
- An undersized additional image is not disapproved, but it is not shown.
- In text feeds, separate URLs with commas and encode commas inside a URL as `%2C`.

## One photo reused across many products

Feeds have no reuse rule, but the content rule bites: each item's image must show **that** product. A
photo of one configuration used for every variant can misrepresent the variants (colour, size, model).
Where variants look different, each needs its own photo; where they look identical (same case, different
internal parts), a shared photo of the visible product is accurate, and the differences belong in the
title and attributes, never in an overlay.

## Other shopping feeds

Microsoft Merchant Center and AI-agent product feeds have their own image rules; their transport and
priority are in `ai-search-optimizer`. Read each platform's current image specification before
submission; do not assume Google's limits carry over.

## Checks before a feed goes out

1. Every `image_link` returns 200 to an anonymous request and is not blocked by robots.txt.
2. Smallest side at least 500 px (the 2027-01-31 rule), file under 16 MB.
3. No overlays: scan banner-style images and anything uploaded by marketing for text.
4. Placeholder images (the platform's "awaiting image") are never sent.
5. Variant items point at a variant photo where the variants look different.
